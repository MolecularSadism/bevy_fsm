## [Unreleased]

## [0.7.0] - 2026-10-25

### Changed

- **BREAKING**: The FSM enum must be an immutable component
  (`#[component(immutable)]`); `#[derive(FSMState)]` enforces this at compile
  time. `&mut` access to the state no longer compiles, so it only changes through
  `StateChangeRequest` or `ResetState`.
- **BREAKING**: `StateChangeRequest` is a `Command` instead of an event: queue it
  with `commands.queue(StateChangeRequest { entity, next })`. The
  `apply_state_request` observer is gone. `StateChangeRequest::try_apply(world)`
  applies a request immediately and returns `Ok(previous)` or a `TransitionError`.
- **BREAKING**: `Enter<K>` and `Exit<K>` are observer patterns over the new
  `EnterEvent<S>` / `ExitEvent<S>` events. `K` is either the FSM enum (every
  variant) or one of its variant markers (that variant only); observer signatures
  such as `On<Enter<life_fsm::Dying>>` and `On<Enter<LifeFSM>>` are unchanged.
  The event's `state` field is now always the FSM enum.
- **BREAKING**: `ExitEvent` carries the destination (`to`) and `EnterEvent` the
  origin (`from`, `None` for the initial state).
- **BREAKING**: Removed `Transition<F, T>`. Observe `Exit` of the source variant
  and check `to` instead.
- **BREAKING**: `FSMState` requires `Hash` and `Debug` and can no longer be implemented by
  hand (use the derive); its `trigger_*_variant` and `can_transition*` methods
  were removed (`FSMTransition` keeps the rules). The derive rejects generic enums.
- Each transition fires one `Exit` and one `Enter` event, routed by the variant
  marker's component id, instead of six typed triggers, and no longer runs an
  intermediate request observer. The derive no longer generates the N²
  transition match: a test crate with one 18-variant FSM generates 2,886 instead
  of 22,867 functions and rebuilds in 0.6 s instead of 2.5 s.
- Variant markers are zero-sized components that cannot be constructed outside
  their generated module, with the enum's visibility.

### Fixed

- A transition requested by an `Exit` observer for the entity it is leaving
  recursed until the stack overflowed (also in 0.6). It is now rejected with
  `TransitionError::Exiting` and a warning. Transitions requested from `Enter`
  observers, including the initial `Enter`, chain as before.

### Added

- `ResetState { entity, state }` command: overwrites the state without
  validation and without events, for re-initialising pooled entities.
- `TransitionError`, `FSMKey`, `EnterEvent`, `ExitEvent`.

### Migration

- Add `#[component(immutable)]` to every FSM enum.
- `commands.trigger(StateChangeRequest { .. })` → `commands.queue(StateChangeRequest { .. })`.
- `On<Transition<a::X, a::Y>>` → `On<Exit<a::X>>` with `if trigger.to == A::Y`.
  `On<Transition<A, A>>` → `On<Exit<A>>` (`state` is the old value, `to` the new).
- Code that wrote the state directly (`get_mut`, `Query<&mut S>`) must request
  the transition or, to skip rules and events, queue `ResetState`.
- Observers that listened to `On<StateChangeRequest<S>>` no longer receive
  anything; observe `Exit`/`Enter` or check the resulting state.
- Observers registered with `add_observer(apply_state_request::<S>)` in tests
  can be dropped; `FSMPlugin` is no longer needed for transitions, only for the
  initial `Enter`, reflection and the observer hierarchy.

## [0.6.0] - 2026-10-22

### Changed

- **BREAKING**: Migrated to Bevy 0.20 (requires Rust 1.97.1). Bevy 0.18 and
  0.19 are no longer supported.
- Removed the CI job that tested against Bevy 0.18.

### Migration

Bevy 0.20 changed lifecycle observers to carry the component bundle as a
generic of the lifecycle type: `On<Add, S>` is now `On<Add<S>>` (likewise
`Insert`, `Remove`, etc.). `on_fsm_added` was updated accordingly. If you
register your own lifecycle observers on FSM components, update them the same
way. No other `bevy_fsm` API changed.

## [0.5.0] - 2026-07-29

### Changed

- **BREAKING**: The `bevy_enum_event` dependency has been dropped. The
  per-variant marker types (e.g. `life_fsm::Dying`) are now generated by
  `#[derive(FSMState)]` itself, so `#[derive(EnumEvent)]` is no longer needed
  (or re-exported from `bevy_fsm`). Remove `EnumEvent` from your derive lists
  and drop the `bevy_enum_event` import.
- Widened the Bevy requirement from `0.19` to `>=0.18, <0.20`. The crate
  compiles and passes its full test suite against both Bevy 0.18 and 0.19, so
  projects still on 0.18 can now use bevy_fsm 0.5. (Bevy 0.17 remains
  unsupported: its `EntityEvent` trait still required `event_target_mut`,
  which was removed in 0.18.)
- Removed `Cargo.lock` from the repository (library crates should not pin
  dependency versions for consumers) and excluded `.github/` and `.gitignore`
  from the published package. Note that `.cargo_vcs_info.json`,
  `Cargo.toml.orig`, and a generated `Cargo.lock` still appear in the
  crates.io tarball — those are injected by `cargo publish` itself for every
  crate and cannot be removed.
- Internal polish: dropped redundant `Component` bounds on `FSMPlugin`
  (`FSMState` already implies `Component`), rewrote a debug-logging test into
  concise assertions, and added a CI job that runs the test suite against the
  minimum supported Bevy version (0.18).

### Notes

The generated marker types are now plain zero-sized structs
(`Clone + Copy + Debug + Default + PartialEq + Eq + Hash`) rather than Bevy
`Event`s. `bevy_fsm` only ever uses them as the type parameter for `Enter<T>`,
`Exit<T>`, and `Transition<F, T>` (which are the actual `EntityEvent`s), so the
event impl was unused. Making the markers inert also means a variant type can no
longer be triggered on its own and silently bypass the state machine.

## [0.4.0] - 2026-07-09

### Changed

- **BREAKING**: Migrated to Bevy 0.19 (requires Rust 1.95.0)

### Notes

The public API required no source changes: the observer system (`On<Event>`,
`On<Add, S>`, `add_observer`), `EntityEvent`, `commands.trigger`, the
`ChildOf`/`add_child` hierarchy, and reflection (`register_type`) all remained
compatible across the 0.18 → 0.19 upgrade. The 0.19 migration reworked several
subsystems this crate relies on, so regression tests were added to pin down the
behaviours that were most at risk:

- `on_fsm_added` (`On<Add, S>`) stays add-only and does not re-fire when a
  transition re-inserts the state component (guards against the `Replace` →
  `Discard` "Lifecycle event changes").
- `apply_state_request` gracefully ignores despawned entities and removed
  components instead of panicking (guards against "SystemParam validation is
  now done when fetching the data").
- Reflection registration and the resource-backed observer hierarchy keep
  working (guards against "Resources as Components" and the `bevy_reflect`
  reorganization).

## [0.3.0] - 2025-01-20

### Changed

- **BREAKING**: Migrated to Bevy 0.18
- **BREAKING**: `EntityEvent::event_target_mut` removed (moved to `SetEntityEventTarget` trait in Bevy 0.18)
- **BREAKING**: Use `trigger.event_target()` instead of `trigger.target()` to access entity in observers
- Updated all documentation examples to use Bevy 0.18 patterns
- Observer entities no longer marked as `Internal` (component removed in Bevy 0.18)

### Fixed

- Tests updated to work without `Internal` component filtering

## [0.2.0] - 2025-10-01

### Changed

- **BREAKING**: Migrated to Bevy 0.17
- **BREAKING**: Observer triggers now use `On<Event>` instead of `Trigger<Event>`
- **BREAKING**: Events now embed entity field, use `trigger()` not `trigger_targets()`
- Updated hierarchy API for Bevy 0.17
- Observer entities marked as `Internal`
- Tests updated for internal entity filtering

## [0.1.0] - 2025-09-15

### Added

- Initial release for Bevy 0.16
- Observer-driven FSM framework
- `FSMState` and `FSMTransition` derive macros
- `FSMPlugin` for automatic observer setup
- `fsm_observer!` macro for hierarchy organization
- `FSMOverride` component for per-entity transition rules
- Enter, Exit, and Transition events
- Variant-specific event types via `EnumEvent`
- Context-aware transition validation with world access
